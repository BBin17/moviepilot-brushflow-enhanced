# 智能刷流 1.3.0

智能刷流是独立的 MoviePilot V3 插件，使用独立的 `SmartBrushFlow` 插件 ID、配置空间、API、任务数据和 qB 标签，不读取或改写旧版“站点刷流”任务。

它面向日常 NAS 用户提供“一套嵌套配置、一条决策链、一个操作入口”。首页健康卡直接回答任务是否正常、插件下一步会做什么，以及是否需要用户处理。

## 核心行为

- 每个任务独立管理站点、下载器、容量、带宽、筛选、下载健康和删种安全；全局容量只阻止继续新增，不跨任务抢占或删种。
- 选种先执行重复、跨站未完成、H&R、促销、明确体积、发布时间和文本硬过滤，再使用本地 30 天收益学习评分。
- Tracker 人数未知时保持中性；可信需求需要最近 3 次检查至少出现 2 次。
- 自动删种永久保护未完成、H&R、未到站点最低保种、排除标签、真实上传和有效活动连接。Tracker 单独报告下载者时先保护；完整观测默认 24 小时零上传、没有连接时重新评估价值。数据不足、采样断档或上传计数重置不会被判成零上传。
- 1.3按真实表现淘汰：完整连续72小时零上传、实际做种也达到72小时且满足站点最低保种时长，通过连续确认后主动淘汰。空间充足也会执行，近期有上传的种子结合单位容量收益评分。
- 容量仅作为新增硬上限，不再设置容量触发/停止线、滚动每日数量或每轮/每日释放GB额度。自动按5个的I/O批次逐个复核，下一次检查继续；手动名单最多10个，不再有25%容量门槛。
- 收益观测不足、计数重置和采样断档继续保护。用户可关闭长期零上传淘汰或调整24–720小时门槛；降低门槛会重新进入安全观察。
- 新启用或从旧版迁移的自动删种先进入 48 小时安全观察，只记录计划、不调用下载器；误判率超标或出现硬安全违规会自动延长。
- 正常低价值淘汰先写完整审计，再删除下载器任务及数据；Tracker 明确拒绝的无效任务只移除任务、保留数据。
- 未完成下载连续 3 次且跨度不少于 30 分钟无进度时，自动重新汇报 Tracker 并恢复一次；再次持续异常则暂停。连续低速也使用“修复一次→仍异常则暂停”，永不自动删除未完成数据。
- 下载健康详情为卡住或低速种子提供逐个手动删除；执行前会重新核对完成状态和进度，默认只移除下载器任务并保留文件，只有用户明确勾选后才删除本地数据。移除请求先写审计，结果不确定时不会自动重试。
- 不同促销、体积与人数组合按各自的样本量降低学习权重；零收益历史不会把后续有效上传永久压成零。选种扣除做种竞争，超过 50GB 需有足够的相对下载需求，单种不超过任务容量的 25%。

旧条件删种、动态删种、全局删种托管、模拟删种和旧兼容引擎在智能刷流 1.1 中不注册或执行。新插件不会迁移旧版“站点刷流”的任务；两套插件可同时安装、独立配置和独立运行。

## 界面

- 首页：响应式任务健康卡、容量、每日上传、异常数量和下一步。
- 收益面板：过去 24 小时实际观测上传、有上传种子、已达最低保种数量、完整 24 小时零上传占用；不足 24 小时的窗口会明确标记。种子表支持零上传/已达保种/下载异常筛选，以及单位容量收益、大小、保种时长排序。
- 下载超过默认 48 小时仍未完成时提醒处理，展示已下载时长和预计剩余时间；修复后自动暂停的任务也会显示为待处理。超时提醒不会自动删除数据。
- 任务详情：概览、种子表现、运行记录；概览先展示上传表现，再区分待淘汰和受保护及其原因，容量只展示当前/上限，学习数据折叠在决策依据中。
- 配置：站点与任务、空间与速度、选种方式、删种与安全四步向导，并在保存前生成白话预览。
- 保存目录：从所选下载器读取实际默认目录和现有任务使用过的目录，可下拉选择；也可手动输入，留空则使用下载器默认目录。
- 工具与设置：插件开关、全局硬上限和独立站点签到；签到不参与刷流决策。

## 迁移

- 数据版本为 9，迁移可重复执行，不覆盖首次保存的升级前备份。
- 1.3首次升级保存`v1_3_task_config_backups`，保留任务开关、永久安全设置、删除数据选择和观察状态；旧容量停止线与释放额度只为备份兼容保留，不参与新引擎。
- 1.2 首次升级保存 `v1_2_policy_backups`，为已启用自动删种的任务重新观察 48 小时；原先关闭或暂停的任务保持原开关，其他配置和历史不变。重复加载不会重新开始计时。
- 保留站点、下载器、目录、标签、调度、分享率目标、容量、带宽、促销、H&R、大小、发布时间、文本筛选、最低保种、排除标签和删除数据选择。
- 旧单值大小解释为最小体积；范围拆为明确最小值和最大值。
- 曾启用智能、动态或条件删种的任务统一迁移到均衡策略并进入 48 小时观察；未设置容量或最低保种时自动暂停删种并提示完善。
- 原来关闭删种的任务保持关闭；种子身份、上传历史、学习数据和审计继续保留。

## API

基础路径为 `/api/v1/plugin/SmartBrushFlow`，均使用宿主 Bearer 认证。

| 方法 | 路径 | 用途 |
| --- | --- | --- |
| `GET` | `/status` | 全局状态、任务健康摘要与可选站点下载器 |
| `GET` | `/downloaders/{downloader}/paths` | 读取指定下载器实际默认目录和现有任务目录 |
| `POST` | `/settings` | 插件、全局硬上限与签到设置 |
| `POST` | `/tasks` | 创建 1.1 嵌套任务 |
| `GET / PUT / DELETE` | `/tasks/{task_id}` | 查询、按 revision 更新或删除任务 |
| `GET` | `/tasks/{task_id}/torrents` | 分页获取任务种子 |
| `GET` | `/tasks/{task_id}/events` | 分页获取运行记录 |
| `POST` | `/tasks/{task_id}/cleanup/preview` | 只读预览本轮清理名单 |
| `POST` | `/tasks/{task_id}/actions/{action}` | 统一任务操作入口 |
| `POST` | `/signin/run` | 立即执行站点签到 |

统一动作包括 `run_selection`、`run_check`、`pause_task`、`resume_task`、`activate_deletion`、`extend_observation`、`pause_deletion`、`resume_deletion`、`retry_stalled`、`pause_stalled` 和 `delete_unhealthy_download`。手动删除动作需要 `torrent_hash`、唯一 `request_id`、`confirm: true`，可选 `delete_data: true`。

## 构建

在本目录执行 `pnpm build`。构建会先验证 Python、插件 `package.json` 与根目录 `package.v3.json` 的发布版本一致性，再验证前端默认值并生成 `dist/assets`。
